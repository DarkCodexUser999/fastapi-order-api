# Family TV independent architecture review

**Scope** · Local main at `cc6cb34`, 19 November 2026. Source, Git history, local historical TV observations and read-only host checks. Historical measurements below retain their original version.

## Verdict

1. Native Java Views and pre-rendered tiles suit this stick. Keep the TV interface native.
2. Focus transitions animate several surfaces, and first entry to a row builds every control during the key event.
3. The gear delegates to Fire OS. Family TV can preserve its own selection but cannot guarantee another app’s BACK behavior.
4. The Flutter client and opt-in LAN server already exist. Command delivery and physical memory acceptance need work before expansion.
5. ADB could not start on this host. Current PSS, input latency, Settings routing and readability at 4 m remain unverified.

## Focus diagnosis

Ranked suspects are **F01** for ordinary presses in every direction, **F02** for an additional first-entry vertical stall, and **F03** for the impression that the screen trails the selection. F03 cannot by itself explain delayed input delivery. The normal tile drawing path reuses its Paint and ring bounds (TileButton.java:13–29, 32–41). Ordinary horizontal focus uses transforms and has no explicit requestLayout, image decode or disk write. Vertical navigation also scans focusTargets via containsValue; measure that separately if catalogs grow. The connected remote marks peers dirty under a monitor, with serialization and socket writes outside the focus callback (lan/EventHub.java:40–48, 82–101).

For a later authorized physical comparison, use the same APK, output mode, catalog and remote. Separate first and subsequent row visits, individual taps and held repeats, all four directions, and LAN off/idle/connected. Record enough repetitions for median and p95 key-to-visible-ring, ring-to-settled-row, and key-to-art. Pair frame evidence with view count and PSS; inspect edge clipping, fallback text and the focused ring from 4 m. A screenshot alone cannot time a key press.

## Keep as is

- Keep Leanback-first discovery, exported/enabled/permission checks, explicit components, hidden filtering before row assignment and the current Sony LIV exclusion. Preserve both package-list asset formats, ordered rows and Prime alias handling.
- Keep one pending tile launch, Hotstar’s Loading… label, visual feedback before dispatch, failure recovery, per-row memory and the restore-on-resume fallback. Existing apps control their internal BACK navigation.
- Keep the native single-control tile, reusable outline, explicit horizontal neighbors, locale-independent matching and worker-side bitmap preparation. Preserve approximate 5% safe margins and check legibility at the intended distance.
- Keep Amazon Home available. The restore script has no system package disable or pm clear command. Its default uninstall targets only Family TV and removes that app’s private state; home-only skips uninstall. The explicit phone-forget and revoke controls affect Family TV credentials.
- Keep the versioned protocol and default-off same-process service, private Wi-Fi bind, platform-keystore identity, TV-confirmed fingerprint, time-limited PIN, hashed TV tokens and foreground-only actions. Preserve detach on pause/stop, callback removal, stale-art checks and transport shutdown. Treat listener references as lifecycle-owned.

| 2 | Extract per-app route policy. Make the gear open local settings and retain a measured Fire TV Settings route. | Medium. Silk, Hotstar and external task behavior need individual regression checks. | Predictable gear interaction and diagnosable BACK behavior. |
| 3 | Make LAN revocation reliable and gate further companion features on physical pairing, input and PSS. | Medium. Exercise Wi-Fi loss, reconnect and Activity recreation. | Reliable loss of access and a known server cost on this stick. |
| 4 | Separate art loading from Views, bound resident bytes, and add cached widescreen TMDB art and readable fallback tiles. | Medium. Larger images can consume the gains from focus work. | Better couch-distance recognition and consistent offline visuals. |
| 5 | Test legacy restore semantics, then remove abandoned HOME and inactive launcher code. | Low with migration fixtures. An older install may still have service tokens or a grant. | Smaller maintenance and permission surface while retaining recovery. |

## Target structure and migration

Keep one installable TV module and one process on the stick. The following are package boundaries inside that module unless already independent.

| Target | Responsibility and migration order |
|---|---|
| tests/ and protocol/ | First capture behavioral contracts for filters, own-task flags including Silk, loading timeout/failure/resume, row memory, gear return and double-run restore. Keep common wire fixtures. |
| launcher/.../catalog/ and launch/ | Move parsed config, ordered catalog snapshots and intent policy behind the Activity’s existing entry points. Keep asset names and package keys stable. Retain actual startActivity and feedback callbacks on the UI thread. |
| launcher/.../ui/ | Isolate focus/rows and launch feedback. Share the same UI dispatcher for physical and phone input. Make the gear and MENU reuse local options. Validate focus before changing art. |
| launcher/.../lan/, mobile/, protocol/ | Retain the existing service and Flutter Android/iOS hosts. Serialize security-sensitive commands reliably before adding routes. Bind on opt-in, reconcile network changes, reject input while paused or launching, recover on next allowed start and close peers/workers on shutdown. Keep discovery optional and pin on manual connections too. |
| launcher/.../artwork/ | Move rasterization and disk/cache ownership out of TopShelf. Preserve overrides under /sdcard/FamilyTV, make the provider optional and retain the last validated image. Change image quality only after lifecycle and byte limits work. |
| remote/, shared/, restore.sh | Keep legacy native remote and shared protocol identifiable until migration acceptance. Remove dead TV paths in a separate change and keep the existing restore entry point. |

**Memory acceptance.** Use the existing same-build target of ≤5 MiB incremental PSS with LAN enabled idle and investigate any result above 8 MiB (docs/ARCHITECTURE.md:75). Sample the package with LAN disabled, idle, paired and with two active peers, then after background/return. Track peak and settled PSS separately during art replacement. At 1280×720, one RGB565 frame alone is 1.76 MiB. Budget for the displayed frame, incoming decode and render surfaces before increasing cache capacity. User-reported system free RAM is not a launcher heap allowance.
